# 幕稿 · 视频脚本编辑器

[![CI](https://github.com/WhoKnowsNothing/mugao-script-writing/actions/workflows/ci.yml/badge.svg)](https://github.com/WhoKnowsNothing/mugao-script-writing/actions/workflows/ci.yml)

支持 Word 与 Markdown 导出的个人视频写稿工具。左侧写口播，右侧记录画面、BGM / 音效和附注。

当前稳定版本为 **v1.0.0**。项目以 MIT License 开源，源码托管在 [GitHub](https://github.com/WhoKnowsNothing/mugao-script-writing)。

## 使用

Windows 双击项目中的 **启动幕稿.cmd**，等启动完成后打开 http://localhost:3000

运行期间保持窗口打开；关闭窗口后网页服务会停止，已保存的文案仍留在浏览器中。

也可以在本目录运行（Node.js 22.13+，验证环境为 Node.js 24.13）：

```sh
npm ci
npm run dev
```

请一直使用 `http://localhost:3000/`。换成 `127.0.0.1`、不同端口、不同浏览器或线上地址，都会使用另一份独立的浏览器存储；切换前先下载 JSON 备份。

## 已实现

- 多份脚本、段落大纲、标题和简介。
- 文案 / 画面 / BGM / 附注双栏编辑，输入框自动增高。
- 可在当前段落上方或下方插入新段落，也支持复制、删除、光标分段与合并。
- 可通过“移动至…”、正文左侧六点拖拽柄或段落大纲拖拽整段排序，文案与制作说明始终成对移动。
- 全文及逐段字数、口播估时、停顿与手动时长。
- 分组撤销和重做。连续输入合为一组，结构操作单独撤销，最多 80 步；关闭页面后撤销历史不保留。
- IndexedDB 自动保存，保存失败提醒，其他标签页的版本冲突保护。
- 编辑期间每分钟保留旧版本，最多十份；历史版本以副本恢复。
- 一键导出 Word `.docx` 文档；下拉菜单保留 Markdown 双栏表格、分段正文及源码预览和复制。
- 复制 Markdown 源码；JSON 完整备份和恢复；整稿粘贴后按空行创建段落。
- 手机端使用单栏段落卡片，制作说明可折叠；脚本抽屉、触控菜单和保存状态适配窄屏。
- 自定义 AI 服务：画面与附注建议、单张配图、固定风格、逐段或整稿润色，以及常用平台风险审查。
- 脚本列表悬停或键盘聚焦时显示三点菜单，可删除对应脚本并撤销；触屏始终显示此入口。
- 导出菜单支持当前单个脚本的 JSON，沿用完整备份格式，可通过现有“导入文案 / 备份”恢复。
- 侧栏“显示设置”统一调节界面、正文和弹窗字号（90%–150%），浏览器会记住选择。默认正文 18px、制作说明 16px，界面常用字号 14–16px；导出的 Word / Markdown / JSON 内容不受影响。

## AI 助手

侧栏打开 **AI 设置**，分别填写文字、生图服务的基础地址、模型名称和 API Key。基础地址通常形如 `https://api.example.com/v1`，不要包含具体接口路径；本机服务可使用 `http://localhost:端口/v1`。模型 ID、可用图片尺寸和费用以服务商为准。可先点“测试文字连接”，该测试只发送一条测试消息，也可能产生服务商费用。

画面建议、润色和审查会通过 `response_format: {"type":"json_object"}` 启用 JSON 输出模式，文字服务需支持此参数；DeepSeek 的要求见[官方 JSON Output 文档](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)。连接测试仅检查普通文字响应，不验证 JSON 输出能力。

生图支持 OpenAI 兼容接口和硅基流动官方接口（`api.siliconflow.cn` / `api.siliconflow.com`）。硅基流动会自动使用 `image_size` 参数并读取 `images` 返回值；Kolors 尺寸留空时使用 `1024x1024`，其他模型留空时采用服务默认尺寸，也可为 Kolors 填写 `720x1280` 等支持的尺寸。不发送已下线的 `batch_size` 参数。HTTP 402 表示服务商账户余额不足或欠费，需要到服务商控制台检查余额与可用额度，重复生成不会解决账户限制。接口与错误码见[硅基流动生图文档](https://api-docs.siliconflow.cn/docs/api/images-generations-post)和[错误排查文档](https://api-docs.siliconflow.cn/docs/userguide/faqs/error-code)。

- **画面建议**：每段制作说明上方有入口，结合口播、已有画面与附注，建议构图、素材和拍摄方式。结果可编辑，默认追加，也可取消勾选后替换。
- **配图栏**：整稿无配图时隐藏，添加图片或 AI 生图成功后自动显示，每段一张，可替换、移除和撤销。支持 20 MB 以内的 PNG / JPEG / WebP，随本机稿件与 JSON 备份保存。复制、移动段落保留图片；分段后图片保留在前段；两段有不同配图时需先移除一张再合并，避免丢图。Word / Markdown 仍仅导出文字。
- **生成配图**：需先有画面或附注。生图只请求一张，支持 base64 返回或 HTTPS 图片链接，成功后自动替换对应段落配图，可撤销。优先下载图片本身保存在本机；跨域下载失败时保留临时链接并提示下载后手动添加。生成期间稿件或配图已变化时，不自动覆盖。
- **固定风格**：在设置中分别保存画面风格和文稿风格，画面建议、生图和润色会自动使用对应提示词。每次调用也可填写补充要求。
- **润色文稿**：编辑工具栏的 AI 助手可选择整稿或单段，对照原文后应用。保留段落标识、制作说明和时长；应用为一次可撤销操作。
- **合规审查**：可记住抖音、小红书、视频号、B站等常用平台，展示风险原文、修改建议及依据，支持定位段落。审查不会自动改稿。

内置平台资料是 **2026-10-05 整理的有限摘要**，不是实时联网或完整的规则库。来源和覆盖范围在审查窗口中可展开查看；超过 30 天会提醒更新。抖音使用公开社区公约，小红书使用社区公约 2.0，B站使用公开总则。**视频号官方正文未能读取核验，默认仅做通用风险提示**。可在“补充平台规则”中粘贴最新内容并注明平台、来源、日期和适用场景；仅填写链接不会自动抓取。模型只审查提供的文字，不能核验图片像素、账号资质、事实真实性或素材授权，也不保证平台过审。返回的风险原文会与稿件核对，但建议本身仍需人工判断。

普通编辑和导出在本机完成。只有用户主动点击生成、审查或连接测试时，才会发送相应内容到所配置的服务；调用前会显示接收服务及处理范围。API Key 默认保存在当前标签页的 `sessionStorage`，刷新保留，关闭标签页后清除；“记住 API Key”会将其明文保存在本网站的 `localStorage`，请只在可信设备使用。可以清除已存密钥。设置和密钥独立于稿件，不进入 JSON、Markdown、Word 或稿件历史。

当前采用浏览器直连，服务商必须支持本站来源的 CORS。公网服务需 HTTPS，不会跟随 API 重定向，也不会自动重试收费请求；文字等待 90 秒、生图等待 180 秒。取消或超时只停止浏览器等待，服务商可能继续处理并计费。长文可逐段处理（文字请求内容上限 60,000 字符，生图提示词 16,000 字符，图片 20 MB）。原稿在生成期间被修改、删除或切换后，会阻止应用过期建议。

### 后续固定服务与套餐

界面通过 `lib/ai/provider.ts` 的 `AiProvider` 接口调用服务；当前 `createCustomProvider` 实现 OpenAI 兼容的 `/chat/completions` 和 `/images/generations`，以及硅基流动生图参数与返回值的适配，未包含其他原生厂商协议或异步生图任务协议。接口参考 [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 和 [Image generation](https://developers.openai.com/api/docs/guides/image-generation)。

商业化时可在该边界增加同站服务适配器，由后台保管你的服务密钥并实现登录、套餐、额度、并发、用量与订单。主密钥不能打包到浏览器；应由后端校验额度、记录请求并保证计费幂等。当前版本没有账号、付款、额度扣减或套餐售卖，不会预先展示不可用的商业入口。

## 手机使用

用手机浏览器打开幕稿的网址即可使用，页面会自动切换为手机布局。每段先写文案，下方填写画面、BGM 和附注；点击“画面与制作说明”可收起或展开，内容仍会保存和导出。

左上角菜单可新建、切换脚本或按大纲跳转。长按段落标题旁或大纲里的六点柄约半秒，看到高亮和“拖拽中”提示后，上下移动到目标位置并松手，即可连同制作说明一起排序；设备支持时会在进入拖拽的一刻轻震一下。靠近屏幕或大纲边缘时会自动滚动，绿色横线表示插入位置。轻点、提前滑动或只长按不移动不会改变顺序，正文区域仍可正常滑动和编辑。段落右上角的“…”也提供上方 / 下方新增、移动、分段、复制和删除。顶部显示保存状态，右上角默认导出 Word，下拉菜单提供 Markdown 和 JSON 备份。

电脑和手机的稿件分别保存在各自的浏览器中；换设备时，用 JSON 备份导出和导入转移。

## 导出和恢复

| 格式              | 用途                                                      | 能否恢复完整工程                 |
| ----------------- | --------------------------------------------------------- | -------------------------------- |
| Markdown 表格     | 并排对照文案和制作说明，适合支持 GFM 的编辑器             | 暂不支持直接解析成工程           |
| Markdown 分段正文 | 长文阅读、继续修改、复制到其他写作工具                    | 可复制正文后按空行导入           |
| Word `.docx`      | 交付剪辑、审稿、打印；A4 三列表格（段号、文案、制作说明） | 暂不支持 Word 导入               |
| JSON              | 导出当前脚本，或备份全部脚本；保留制作说明、顺序、语速与手动时长 | 支持；恢复成副本，不覆盖已有脚本 |

Markdown 会转义特殊字符，表格换行使用 `<br>`。粘贴进去的正文按纯文本处理，不执行 HTML、不解释 Markdown 富文本。

## 计时规则

字数是文案内的 Unicode 文字与数字个数，不含标点、空白、表情，也不计标题和制作说明。英文单词会另外按词参与估时。

口播秒数 = 中文及数字等非拉丁字符 / 中文每分钟字数 × 60 + 英文单词 / 英文每分钟词数 × 60。默认中文 240 字/分钟，英文 150 词/分钟。英文缩写和复杂数字的实际读法可能不同，须试读校准。

自动计划时长 = 口播秒数 + 设置的额外停顿；有手动时长时，直接使用手动值，不再叠加停顿。标点不会自动增加停顿。

分段时制作说明保留在前半段，停顿移到后半段；手动时长按文本长度比例分配。合并时两段各栏文字和停顿都会保留；如果任一段有手动时长，合并结果使用两段当前计划时长的总和。

## 数据与限制

所有稿件只保存到**当前浏览器、当前网址**。没有账号、云同步或协同编辑。清理网站数据、删除浏览器配置、无痕模式关闭或存储被浏览器清理，都可能失去本机记录。请定期把 JSON 下载到自己的文件夹；本机历史也不是独立备份。

编辑后约 350 毫秒启动保存；以“已保存到本机”提示为准。突然断电或浏览器崩溃前尚未保存的文字无法保证恢复。两个标签页同时编辑时，不会自动合并：冲突页面暂停保存、保留内存稿件，先下载备份后再载入最新版本。

每份脚本最多 500 段，本机最多 100 份；单栏最多 50,000 字符，单张配图最多 20 MB，JSON 导入最多 128 MB。添加图片时也检查备份大小，避免产生无法恢复的超限备份。Word 导出在浏览器本地生成。大型脚本可能需要更长时间。

## 开发与验证

### 合入个人网站

运行 `npm run build:static` 可生成 `out/mugao/`，部署路径固定为 `/mugao/`。
这个版本复用同一套编辑器、浏览器存储和导出功能，只需静态文件服务，不需要 Node.js 后台或数据库。
侧栏的“返回勿知鸦”链接回到 `/#mugao`，沿用个人网站现有的项目抽屉。

个人网站位于 `../wuzhiya`。在该目录运行 `npm run prepare:mugao` 后，使用它的 `deploy/mugao.Dockerfile` 构建幕稿镜像；`deploy/homepage.Dockerfile` 单独构建主页镜像。共享入口将 `/mugao/` 转发给幕稿，两者可以分别更新。具体命令见个人网站的 README。

首次从 localhost、Sites 或其他网址切换过来时，先在旧网址导出 JSON 备份，再到 `/mugao/` 导入；同一正式网址更新镜像不影响浏览器内的稿件。

### 检查命令

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

React 19 + TypeScript + Vinext / Vite，使用 shadcn / Base UI、Lucide、IndexedDB（idb）和 docx。只保留用到的 UI 组件。可选自带密钥调用 AI 服务，项目没有内置服务密钥、数据库后台或套餐计费系统。`.openai/hosting.json` 保留 Sites 兼容配置，不影响本地编辑。

测试覆盖中文/英文/Unicode 计数、计时、结构操作、撤销与重做、JSON 往返和非法数据、Markdown 特殊字符、DOCX 结构、保存恢复、失败保护及多标签页并发写入。组件测试使用 jsdom；另在浏览器中检查手机尺寸下的新建、编辑、制作说明折叠、段落移动、撤销、重做、刷新恢复和导出预览，并检查 320–900 像素窄屏、横屏和桌面布局。实体手机、软键盘和实际中文输入法的人工验收尚未进行。

`scripts/export-sample.mjs` 使用与网页相同的导出代码生成样例；需 Node.js 22.18+ 的 TypeScript 类型擦除支持。Word 格式使用明确 A4 尺寸与表格列宽，中文字体为微软雅黑。正常短段落不拆页；超长段落允许跨页并重复表头。
