# 幕稿 · 视频脚本编辑器

[![CI](https://github.com/WhoKnowsNothing/mugao-script-writing/actions/workflows/ci.yml/badge.svg)](https://github.com/WhoKnowsNothing/mugao-script-writing/actions/workflows/ci.yml)

以 Markdown 导出为主的个人视频写稿工具。左侧写口播，右侧记录画面、BGM / 音效和附注。

当前稳定版本为 **v1.0.0**。项目以 MIT License 开源，源码托管在 [GitHub](https://github.com/WhoKnowsNothing/mugao-script-writing)。

## 使用

Windows 双击项目中的 **启动幕稿.cmd**，等启动完成后打开 http://localhost:3000


运行期间保持窗口打开；关闭窗口后网页服务会停止，已保存的文案仍留在浏览器中。

也可以在本目录运行（Node.js 22.13+，验证环境为 Node.js 24.13）：

```sh
npm ci
npm run dev
```

请一直使用 `http://localhost:3000/`。换成 `127.0.0.1`、不同端口、不同浏览器或线上地址，都会使用另一份独立的浏览器存储；切换前先下载 JSON 备份。

## 已实现

- 多份脚本、段落大纲、标题和简介。
- 文案 / 画面 / BGM / 附注双栏编辑，输入框自动增高。
- 可在当前段落上方或下方插入新段落，也支持复制、删除、光标分段与合并。
- 可通过“移动至…”、正文左侧六点拖拽柄或段落大纲拖拽整段排序，文案与制作说明始终成对移动。
- 全文及逐段字数、口播估时、停顿与手动时长。
- 分组撤销和重做。连续输入合为一组，结构操作单独撤销，最多 80 步；关闭页面后撤销历史不保留。
- IndexedDB 自动保存，保存失败提醒，其他标签页的版本冲突保护。
- 编辑期间每分钟保留旧版本，最多十份；历史版本以副本恢复。
- 一键 Markdown 表格导出；可选 Markdown 分段正文、真正的 Word `.docx` 文档。
- 复制 Markdown 源码；JSON 完整备份和恢复；整稿粘贴后按空行创建段落。
- 窄屏时展开脚本列表，手机宽度下分上下栏。

## 导出和恢复

| 格式              | 用途                                                      | 能否恢复完整工程                 |
| ----------------- | --------------------------------------------------------- | -------------------------------- |
| Markdown 表格     | 并排对照文案和制作说明，适合支持 GFM 的编辑器             | 暂不支持直接解析成工程           |
| Markdown 分段正文 | 长文阅读、继续修改、复制到其他写作工具                    | 可复制正文后按空行导入           |
| Word `.docx`      | 交付剪辑、审稿、打印；A4 三列表格（段号、文案、制作说明） | 暂不支持 Word 导入               |
| JSON              | 保留所有脚本、制作说明、顺序、语速与手动时长              | 支持；恢复成副本，不覆盖已有脚本 |

Markdown 会转义特殊字符，表格换行使用 `<br>`。粘贴进去的正文按纯文本处理，不执行 HTML、不解释 Markdown 富文本。

## 计时规则

字数是文案内的 Unicode 文字与数字个数，不含标点、空白、表情，也不计标题和右栏制作说明。英文单词会另外按词参与估时。

口播秒数 = 中文及数字等非拉丁字符 / 中文每分钟字数 × 60 + 英文单词 / 英文每分钟词数 × 60。默认中文 240 字/分钟，英文 150 词/分钟。英文缩写和复杂数字的实际读法可能不同，须试读校准。

自动计划时长 = 口播秒数 + 设置的额外停顿；有手动时长时，直接使用手动值，不再叠加停顿。标点不会自动增加停顿。

分段时制作说明保留在前半段，停顿移到后半段；手动时长按文本长度比例分配。合并时两段各栏文字和停顿都会保留；如果任一段有手动时长，合并结果使用两段当前计划时长的总和。

## 数据与限制

所有稿件只保存到**当前浏览器、当前网址**。没有账号、云同步或协同编辑。清理网站数据、删除浏览器配置、无痕模式关闭或存储被浏览器清理，都可能失去本机记录。请定期把 JSON 下载到自己的文件夹；本机历史也不是独立备份。

编辑后约 350 毫秒启动保存；以“已保存到本机”提示为准。突然断电或浏览器崩溃前尚未保存的文字无法保证恢复。两个标签页同时编辑时，不会自动合并：冲突页面暂停保存、保留内存稿件，先下载备份后再载入最新版本。

每份脚本最多 500 段，本机最多 100 份；单栏最多 50,000 字符，JSON 导入最多 8 MB。Word 导出在浏览器本地生成。大型脚本可能需要更长时间。

## 开发与验证

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

React 19 + TypeScript + Vinext / Vite，使用 shadcn / Base UI、Lucide、IndexedDB（idb）和 docx。只保留用到的 UI 组件。没有数据库服务、AI API key 或按调用计费的功能。`.openai/hosting.json` 保留 Sites 兼容配置，不影响本地编辑。

测试覆盖中文/英文/Unicode 计数、计时、结构操作、撤销与重做、JSON 往返和非法数据、Markdown 特殊字符、DOCX 结构、保存恢复、失败保护及多标签页并发写入。组件测试使用 jsdom；另外在本机 Chrome 中检查了新建、编辑、段落移动、撤销、重做、刷新恢复和导出按钮。手机和实际中文输入法的人工验收尚未进行。

`scripts/export-sample.mjs` 使用与网页相同的导出代码生成样例；需 Node.js 22.18+ 的 TypeScript 类型擦除支持。Word 格式使用明确 A4 尺寸与表格列宽，中文字体为微软雅黑。正常短段落不拆页；超长段落允许跨页并重复表头。

## 目录

```text
app/                     页面入口、全局主题
components/script-editor.tsx   编辑界面
components/editor-fields.tsx   自动增高和数值输入
components/ui/           实际使用的基础控件
hooks/use-workspace.ts   撤销、保存、页面冲突
lib/script.ts            数据模型、校验、计时、段落操作
lib/storage.ts           IndexedDB 事务与历史
lib/export-markdown.ts   Markdown / JSON 导出
lib/export-docx.ts       Word 文档生成（按需加载）
tests/                   逻辑与组件检查
scripts/                 辅助脚本
```
